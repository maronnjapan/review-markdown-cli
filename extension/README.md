# 字幕メモ (Meet Captions Memo)

Google Meetの字幕(Caption)を自動で読み取り、ローカルの拡張機能ストレージに
「メモ」として保存する個人用Chrome拡張機能です。既定では外部サーバーへの送信は一切行いません。
設定画面から明示的に有効にした場合だけ、同じ端末で動く
[review-markdown-cli](https://github.com/maronnjapan/review-markdown-cli)のローカルサーバー
（`http://localhost`）へも発言を送ります（「[review-markdown-cliとのリアルタイム連携](#review-markdown-cliとのリアルタイム連携)」）。

## できること

- Meetで字幕(CC)をオンにしている間、話者名と発言テキストを自動で記録
- 記録は会議ごとに1件の「メモ」としてまとまる
- 拡張機能のアイコンをクリックすると、保存済みメモの一覧・全文表示・コピー・
  Markdownファイルとしてのダウンロード・削除ができる
- 記録は自分の画面にだけ表示される小さなバッジ(右下)でオン/オフを切り替え可能
- （任意）review-markdown-cliを起動しておくと、確定した発言を1行ずつリアルタイムで
  そのファイルへ書き足せる。書き足した文字起こしをもとに、review-markdown-cliのAIチャットで
  議事録を作ってもらえる

## インストール方法

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」をクリック
4. このフォルダ(`meet-captions-memo`)を選択する

## 使い方

1. Google Meetの会議に参加する
2. Meet側の「字幕をオンにする」(CC)ボタンを押して字幕を表示させる
   (この拡張機能は自動でCCをオンにはしません)
3. 画面右下に「字幕メモ: 記録中」というバッジが出れば認識できています
4. 会議が終わったら、拡張機能アイコンをクリックしてメモを確認
   - 「表示」で全文プレビュー
   - 「コピー」でMarkdown形式のテキストをクリップボードにコピー
     (AIチャットへの貼り付けや、既存の作業ガイド作成フローにそのまま使えます)
   - 「保存(.md)」でダウンロードフォルダの `meet-captions/` 以下にファイル保存
   - 「削除」でそのメモを削除

バッジをクリックすると記録の一時停止/再開ができます。

## 保存場所とデータの扱い

- すべて `chrome.storage.local`(この拡張機能専用のローカル領域)に保存されます
- 外部サーバー・API・アカウントとの通信は行いません
- ブラウザのプロフィールに紐づくため、Chromeを削除したりプロフィールを変えると
  消えます。大事なメモは早めにコピーかダウンロードしておいてください
- 複数のMeetタブを同時に開いた場合、それぞれ別のメモとして記録されます

## review-markdown-cliとのリアルタイム連携

同じ端末で [review-markdown-cli](https://github.com/maronnjapan/review-markdown-cli)
（Markdown/PDFをブラウザでレビューするローカルCLI）を起動している場合、確定した発言を
1行ずつそのローカルサーバーへも送り、指定したMarkdownファイルへ追記できます。
議事録はreview-markdown-cli側の「AIチャット」から作れます（文書全体を対象に「この文字起こしを
元に議事録を作ってください」のように聞いてください）。

既定では無効です。有効にするまでは、この節の通信は一切発生しません。

### 設定のしかた

1. review-markdown-cliを起動し、起動ログの `live captions token` の行をコピーする
   （このトークンは起動のたびに変わります）
2. この拡張機能のアイコンをクリックし、「review-markdown連携」を開く
3. 次の4つを入力して保存する
   - 連携を有効にする（チェックボックス）
   - サーバーURL（既定のポートなら `http://localhost:3000`）
   - トークン（手順1でコピーしたもの）
   - 書き込み先ファイル（review-markdown-cliのレビュー対象ディレクトリからの相対パス。
     例: `meeting-notes/today.md`。存在しなければ最初の発言で作成されます）
4. Meetで字幕(CC)をオンにして会議に参加する。画面右下のバッジに「・連携中」と出ていれば
   送信できています。「・連携エラー」の場合はreview-markdown-cliが起動しているか、
   トークンとURLが合っているかを確認してください

### 送っている内容と送っていないもの

- 送るのは、確定した発言（話者名・本文・時刻）と、会議のタイトル・会議コード・開始時刻
  （書き込み先ファイルをこれから作る場合の見出しに使う）だけです
- 送信先は、入力したサーバーURL（既定は `http://localhost` 配下）だけです。
  それ以外のホストへは送信しません
- chrome.storage.localへの記録は、連携の成否にかかわらずこれまで通り行われます。
  連携が失敗しても、拡張機能側のメモは失われません
- 連携を無効にすれば、この節の通信はすぐに止まります

## 既知の制限

- **字幕そのものの精度に依存**します。Google側の音声認識が誤変換・省略・
  句読点なしのテキストを出すことがあり、記録もそれをそのまま反映します
- **字幕がオンの間しか記録できません**。字幕表示が公式の文字起こし機能や
  録画データそのものより情報量が少ない場合があります
- **話者の識別は名前表示に依存**するため、名前が正しく表示されない環境
  (匿名参加など)では話者名が「話者1」のような仮の表示になることがあります
- 同じ話者が短い間隔で続けて発言すると、まれに1つの発言として繋がって
  記録されることがあります

## 字幕が取得できなくなったとき

Google Meetの内部DOM構造は公開されておらず、UI変更で読み取りが壊れる
ことがあります。バッジが「記録中」にならない・行数が増えない場合:

1. Meet画面でF12(開発者ツール)を開き、字幕が表示されている要素を右クリック
   →「検証」でDOM構造を確認する
2. `content.js` 内の `findCaptionsRegion()` 関数を、実際のDOM構造に合わせて
   セレクタを調整する(現状は `role="region"` かつ `aria-label` に
   "Captions"/"字幕" を含む要素を優先し、見つからない場合はアバター画像を
   手掛かりに推測しています)
3. `chrome://extensions` でこの拡張機能の「再読み込み」ボタンを押してから
   Meetのタブをリロードする

## 注意事項

会議の発言を記録することになるため、社内規定や会議の性質によっては
参加者への事前の断りが必要な場合があります。運用前に念のためご確認ください。
