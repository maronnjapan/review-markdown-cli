# 字幕メモ (Meet Captions Memo)

Google Meetの字幕(Caption)を自動で読み取り、ローカルの拡張機能ストレージに
「メモ」として保存する個人用Chrome拡張機能です。

**外部のサーバーへは何も送りません。** 送る相手は、同じ端末で動く review-markdown の
ローカルサーバー（`http://localhost`）だけです。動いているものを見つけたら自動で繋いで、
確定した発言を書き足します（「[review-markdownとのリアルタイム連携](#review-markdownとのリアルタイム連携)」）。
会議に入ったときの字幕(CC)も自動でオンにします。どちらも拡張機能の設定から止められます。

**自動にしてあるのは、忘れると取り返しがつかないからです。** 字幕をオンにし忘れれば、
その会議は1行も残りません。連携コードを貼り直し忘れれば、記録はされても手元のファイルには
届きません。どちらも気づくのは会議が終わってからです。

この拡張機能は review-markdown（`review-markdown-cli`）に同梱されています。以前は
`meet-captions-memo` という別リポジトリでしたが、CLIと拡張機能は一緒に直さないと繋がりが
壊れるので、1つのリポジトリにまとめました。

## できること

- 会議に入ると字幕(CC)を自動でオンにする（押し忘れても記録が始まる）
- 字幕が出ている間、話者名と発言テキストを自動で記録
- 記録は会議ごとに1件の「メモ」としてまとまる
- 拡張機能のアイコンをクリックすると、保存済みメモの一覧・全文表示・コピー・
  Markdownファイルとしてのダウンロード・削除ができる
- 記録は自分の画面にだけ表示される小さなバッジ(右下)でオン/オフを切り替え可能
- review-markdownを起動しておくと、確定した発言を1行ずつリアルタイムでそのファイルへ
  書き足す。連携コードは拡張機能が自分で取りに行くので、貼る作業はない。書き足した
  文字起こしをもとに、review-markdownのAIチャットで議事録を作ってもらえる

## インストール方法

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」をクリック
4. このフォルダ(`extension`)を選択する

フォルダの場所が分からないときは、CLI側で次のコマンドを実行すると出ます。

```bash
review-markdown extension          # フォルダの場所と読み込ませ方
review-markdown extension --path   # パスだけ
```

## 使い方

1. Google Meetの会議に参加する
2. 字幕(CC)は自動でオンになります（拡張機能の「会議に入ったら字幕(CC)を自動でオンにする」
   を外すと、これまで通り自分で押す形になります）
3. 画面右下に「字幕メモ: 記録中」というバッジが出れば認識できています
4. 会議が終わったら、拡張機能アイコンをクリックしてメモを確認
   - 「表示」で全文プレビュー
   - 「コピー」でMarkdown形式のテキストをクリップボードにコピー
     (AIチャットへの貼り付けや、既存の作業ガイド作成フローにそのまま使えます)
   - 「保存(.md)」でダウンロードフォルダの `meet-captions/` 以下にファイル保存
   - 「削除」でそのメモを削除

バッジをクリックすると記録の一時停止/再開ができます。

## 保存場所とデータの扱い

- すべて `chrome.storage.local`(この拡張機能専用のローカル領域)に保存されます
- 外部サーバー・API・アカウントとの通信は行いません（通信する相手は、同じ端末で動く
  review-markdownだけです）
- ブラウザのプロフィールに紐づくため、Chromeを削除したりプロフィールを変えると
  消えます。大事なメモは早めにコピーかダウンロードしておいてください
- 複数のMeetタブを同時に開いた場合、それぞれ別のメモとして記録されます

## review-markdownとのリアルタイム連携

同じ端末で review-markdown（MarkdownやPDFをブラウザでレビューするローカルCLI）を起動している場合、
確定した発言を1行ずつそのローカルサーバーへも送り、指定したMarkdownファイルへ追記できます。
議事録はreview-markdown側の「AIチャット」から作れます（文書全体を対象に「この文字起こしを
元に議事録を作ってください」のように聞いてください）。

### 繋ぎ方

1. review-markdownを起動する
2. Meetの会議に入る

これだけです。拡張機能が、同じ端末で動いているreview-markdownを自分で探して繋ぎます。
探す先は、前に繋がった場所、いま開いているreview-markdownのタブ、`127.0.0.1` の既定ポート
（3000から10個）の順です。当たった時点で止めるので、ふだんは1回問い合わせるだけです。
トークンは起動のたびに変わりますが、繋ぎ直すのも拡張機能の仕事なので、貼り直しは要りません。

画面右下のバッジの読み方は次のとおりです。

- `・連携中` …… 送れています
- `・review-markdownを探しています` …… 繋ぎ先を探している最中です
- `・連携エラー` …… 見つかりませんでした。review-markdownが起動しているかを確認してください
- `・連携コードを貼り直してください` …… 繋ぎ直しても断られました。下の「手で貼る」で直せます

書き込み先は、何も選ばなければ会議ごとのファイル（`meet-captions/<日付>-<会議コード>.md`）です。
会議のたびにパスを書き換えなくて済み、書き換え忘れて前の会議へ続きが混ざることもありません。

書き込めるのは、review-markdown側で**文字起こし用に決めたファイル**だけです（既定は
`meet-captions/` 配下と、`*.transcript.md`。review-markdown側の `transcriptFiles` で変えられます）。
原稿のパスを書いたまま繋いで、本文の途中に発言が挟まっていくのを防ぐためです。決まったファイルへ
書きたいときは、ポップアップの「会議ごとにファイルを自動で作る」を外し、候補から選ぶか、パスを
直接書きます（例: `meet-captions/today.md`。存在しなければ最初の発言で作成されます）。決まりから
外れたパスへ送ると、書かずに断られ、その理由が返ります。

### 自動で見つからないとき（手で貼る）

既定と違うポートで動かしていて、review-markdownの画面も開いていないときは、見つけられません。
そのときだけ、これまで通り連携コードを貼ります。人が運ぶのは**連携コード1本**だけで、サーバーの
URLとトークンが1つにまとまっているので、片方だけ古いという食い違いは起きません。

1. review-markdownの画面右上の「Meet連携」から連携コードをコピーする（ターミナルの起動ログにも出ます）
2. この拡張機能のアイコンをクリックし、「review-markdown連携」を開く
3. 「連携コード」へ貼り付ける。貼ると、その下に接続先（`http://localhost:3000` など）が出ます
4. 「接続を確認」を押す。書き込まずに繋がるかどうかと、どのディレクトリへ書き込むことになるのかが
   出ます。同時に、書き込み先の候補と、書き込めるファイルの決まりも引いてきます
5. 「連携を有効にする」にチェックが入っていることを確かめて保存する

### 自動をやめるには

- **「review-markdownを自動で見つけて連携する」を外す** …… 探すのをやめます。localhostへは
  一切問い合わせません。繋ぎたいときは連携コードを貼ります
- **「連携を有効にする」を外して保存する** …… 送信をやめます。自分で外した選択は覚えているので、
  review-markdownを見つけても勝手には戻りません

### 送っている内容と送っていないもの

- 送るのは、確定した発言（話者名・本文・時刻）と、会議のタイトル・会議コード・開始時刻
  （書き込み先ファイルをこれから作る場合の見出しに使う）だけです
- 送信先は、連携先として持っているサーバーURLだけです。指せるのは `localhost` / `127.0.0.1` に
  限られていて、それ以外のホストは、探し当てたものも貼り付けたコードも読み込みの時点で断ります
  （`pairing.js` / `background.js`）。行き先は人には読めないので、読めないものを信じさせない
  ための関門です
- 連携先を探すときに送るのは「review-markdownですか」という問い合わせだけです
  （`/api/live-captions/pairing`）。発言は一切乗りません。答えたURLが問い合わせ先と違う相手は、
  連携先にしません
- 探すのは、Meetのタブを開いたとき・ポップアップを開いたとき・送信を断られたときだけです。
  当たりが分かっているときは、そこ1か所しか叩きません
- 「接続を確認」で叩くのは確認専用の窓口（`/api/live-captions/ping`）と、書き込み先の候補を
  返す窓口（`/api/live-captions/targets`）です。どちらもファイルを書き換えません
- chrome.storage.localへの記録は、連携の成否にかかわらずこれまで通り行われます。
  連携が失敗しても、拡張機能側のメモは失われません
- 連携を無効にすれば、この節の通信はすぐに止まります。「自動で見つけて連携する」も外すと、
  探すための問い合わせも止まります

## 既知の制限

- **字幕そのものの精度に依存**します。Google側の音声認識が誤変換・省略・
  句読点なしのテキストを出すことがあり、記録もそれをそのまま反映します
- **字幕がオンの間しか記録できません**。字幕表示が公式の文字起こし機能や
  録画データそのものより情報量が少ない場合があります
- **字幕の自動オンは、Meetのボタンを押すことで実現しています**。Google側のUI変更で
  ボタンが見つからなくなると、何も押さずに諦めます（別のボタンを誤って押さないため）。
  バッジが「記録中」にならないときは、字幕が出ているかを見てください
- **話者の識別は名前表示に依存**するため、名前が正しく表示されない環境
  (匿名参加など)では話者名が「話者1」のような仮の表示になることがあります
- 同じ話者が短い間隔で続けて発言すると、まれに1つの発言として繋がって
  記録されることがあります

## 字幕が取得できなくなったとき

Google Meetの内部DOM構造は公開されておらず、UI変更で読み取りが壊れる
ことがあります。バッジが「記録中」にならない・行数が増えない場合:

1. Meet画面でF12(開発者ツール)を開き、字幕が表示されている要素を右クリック
   →「検証」でDOM構造を確認する
2. `content.js` 内の `findCaptionsRegion()` / `parseRows()` を、実際のDOM構造に
   合わせて調整する。現状は次の順でフォールバックしている:
   1. `role="region"` かつ `aria-label` に "Captions"/"字幕" を含む要素
   2. 既知のクラス名(`.nMcdL` などの行コンテナ、`.ygicle`/`.iTTPOb` などの
      テキスト要素、`.NWpY1d`/`.zs7s8d.jxFHg` などの話者名要素。いずれも
      難読化された名前でGoogle側の変更で失効しうる)
   3. アバター画像(`googleusercontent.com`)を手掛かりにした構造的な推測
3. `chrome://extensions` でこの拡張機能の「再読み込み」ボタンを押してから
   Meetのタブをリロードする

## 注意事項

会議の発言を記録することになるため、社内規定や会議の性質によっては
参加者への事前の断りが必要な場合があります。運用前に念のためご確認ください。
