# 統合の実例(ゲート判定・マージ・質問統合)

統合レポート全文の実例ではなく、パイプライン固有の3つの操作(ゲート判定・重複マージ・質問統合)と、エグゼクティブサマリの粒度を示す抜粋集。サンプル文書は各サブスキルの references/worked-example.md と共通(パスキー導入提案)。**Step 3の統合前に必ず読むこと。**

## 1. ゲート判定ログの例

```
Phase 1(目的定義): Critical 2件(手段の目的化 / 成功基準なし)
→ c1 = 2 ≥ 1 → 目的ゲート発動
→ phase2_mode = overview, phase3_mode = overview

Phase 2(カスケード・概観): ノード抽出+ツリー構築のみ。指摘上位3件。
Phase 3(端的さ・概観): プロファイル+問いリスト+充足マトリクスのみ。欠落上位3件。
```

## 2. エグゼクティブサマリの例(粒度の基準)

```
## エグゼクティブサマリ
- 総合判定: 要再設計 — 目的が手段で書かれ、承認判断に必要な情報の大半が未定義。構成をいじる前に目的と成功基準の確定が必要。
- いま直すべき上位3点:
  1. 目的を「達成状態」で定義し直す(質問1)— これが決まらないと以降の全修正が仮組みになる。
  2. 依頼事項(何の承認を求めるか)を冒頭に明記する(質問2)。
  3. 試験導入→全社展開の間に「進んでよい条件」の中間目標を定義する(質問3)。
- ゲート発動: 目的ゲート発動。カスケード・端的さは概観に留めた。目的修正後の再レビューを推奨。
```

書き方の注意: 上位3点は「フェーズ横断で、直したときの効果順」。各点に対応する質問番号を付け、著者が次の行動に直結できる形にする。

## 3. 重複マージの例

同一引用「ユーザー体験の向上とセキュリティの強化が期待できる」への指摘が2フェーズから出た場合:

- 目的フェーズ(1): 便益の主語欠落+抽象語シェルター
- 端的さフェーズ(3): Q3「やると何が良くなる?」の回答が一部(大きさなし)

→ フェーズ順位の最小は目的(1)。**目的フェーズ側に1件だけ残す**:

```
[M-1] 原文引用: 「ユーザー体験の向上とセキュリティの強化が期待できる」
  問題(便益の主語欠落+抽象語シェルター): …
  修正案: … →質問4。
  (関連: 端的さ観点では、承認者の問い「やると何が良くなる?」への回答不足として同じ箇所が該当)
```

端的さフェーズの詳細指摘からは削除する(充足マトリクスの「一部」判定はそのまま残してよい。マトリクスは指摘ではなく事実の一覧のため)。

## 4. 質問統合の例

- 目的フェーズの質問「パスワードリセット依頼の現状件数と対応工数は?」
- 端的さフェーズの質問「リセット依頼の現状件数は?(効果の数値化のため)」

→ 同じ情報を求めている → 1つにマージ:

```
3. パスワードリセット依頼の現状件数と1件あたりの対応工数は?(便益の数値化と成功基準の設定に使用)
```

マージ後、本文中の【要確認: 質問N】の番号を新しい通し番号に更新することを忘れない。

## 5. やってはいけない統合(アンチパターン)

- **ホチキス留め**: 3本のレポートをそのまま連結する。→ 重複が残り、著者は同じ指摘を3回読まされる。
- **概観フェーズの水増し**: ゲート発動中なのに端的さの詳細指摘を7件並べる。→ 概観は上位3件・各3行以内。
- **質問番号の不整合**: 統合で番号を振り直したのに本文の【要確認: 質問N】が旧番号のまま。→ セルフチェック6で照合する。
