# 目的定義レビュー (Purpose Definition Review)

## このスキルの役割

文書に書かれた「なぜやるのか(Why)・何を達成するのか(What)・達成すると何が良くなるのか(Benefit)・どうなれば達成と言えるのか(成功基準)」の定義品質だけを深くレビューする。目的定義の失敗は文書の他のすべてを無意味にするため、表現や構成には踏み込まず、定義の中身だけを見る。

**スコープ外**(気づいても深追いしない): 目標→行動の接続構造(→ goal-cascade-review)、情報の過不足・文章の認知負荷(→ concision-review)。該当スキルの利用を一言添えるに留める。

## 実行原則(固定プロトコル)

このスキルは、実行するモデルの能力に依存せず同品質のレビューを出すために、判断を手順・判定表・語彙リスト・実例に外部化してある。実行モデルは以下を厳守すること:

1. Stepの省略・順序変更・独自アレンジをしない。
2. 指定された references を指定タイミングで必ず読む。
3. 判定は必ず本文の判定表・語彙リスト・質問バッテリーを適用して行う。「なんとなく問題」という直感だけの指摘は禁止。
4. 出力の粒度・書式・トーンに迷ったら references/worked-example.md の実例に合わせる。
5. 出力前にセルフチェックを実施し、不合格項目があれば修正してから出力する。

## レビュー手順

### Step 0: 準備(必須・省略禁止)
1. references/failure-patterns.md を全文読む(パターン名を指摘に添えるため)。
2. references/worked-example.md を全文読む(出力の粒度・書式の基準)。
3. 文書種別を判定する: タイトル・冒頭に「提案/稟議/申請/承認/決裁/投資」の語があれば **承認系**、なければ **非承認系**(判定表の行8/9で使う)。

### Step 1: 目的記述の全抽出
文書全体から次のシグナルに一致する文をすべて抜き出し、P1, P2, ... と番号を付けた引用リストを作る。以降の全Stepはこの番号を参照する。
- 見出し「目的/背景/ゴール/狙い/ねらい/課題/期待効果/Objective/Goal/Why」配下の文
- 本文中の「〜のため」「〜を目指す」「〜が狙い」「〜を目的と」「〜を実現する」「〜が期待できる」を含む文

抽出がゼロの場合: それ自体を判定表の行1(Critical)とし、Step 2の全観点を「なし」としてStep 7へ進む。

### Step 2: 4観点への分類と欠落マトリクス
各P番号を以下の4観点に分類する(1つのPが複数観点に属してもよい)。観点ごとに判定: 「明確」の条件を満たすPが1つ以上→**明確** / Pはあるが条件を満たさない→**弱い** / Pがゼロ→**なし**。

| 観点 | 問い | 「明確」の条件 |
|---|---|---|
| Why(背景・課題) | 現状の何が問題か。放置するとどうなるか | 数値・頻度・固有の事例のいずれかで裏付けられている |
| What(目的=達成状態) | 終わったとき何が成立しているか | 手段ではなく状態で書かれ(Step 3で判定)、第三者が達成/未達成を判定できる |
| Benefit(便益・貢献) | 達成すると誰の何がどう良くなるか | 貢献チェーン(Step 6)が【断絶】なしで繋がる |
| 成功基準 | 何をどう測れば達成と言えるか | Step 5の3問バッテリーが全問Yes |

### Step 3: 手段/目的の機械判定
Whatに分類された各Pに2つのテストを適用する。

- **テストA(動詞判定)**: 文の主動詞が手段動詞リスト【導入する / 実装する / 構築する / 移行する / 開発する / 作成する / 整備する / 展開する / 採用する / 適用する / 実施する / 開催する / 策定する / 刷新する / リプレイスする / 導入を推進する】のいずれかに該当するか。
- **テストB(上位問いテスト)**: そのPに「それは何のため?」と問うたとき、より上位の目的を1文で書けるか(文書内に答えがある、または常識的に上位目的が明らかに存在する)。

判定: **AとBの両方Yes → 手段の目的化(パターン1)確定**。片方のみYes → 保留とし、もう一方を再確認して結論を出す。両方No → 目的として妥当。

### Step 4: 抽象語シェルターの機械判定
Why / What / Benefit に分類された各Pに適用する。以下の**両方**を満たせば該当(パターン2):
1. 抽象語リスト【効率化 / 最適化 / 強化 / 推進 / 活性化 / 高度化 / 円滑化 / 迅速化 / モダナイゼーション / DX / シナジー / 変革 / (体験・品質・生産性・満足度・利便性など+)向上 / (単独の)改善】の語を含む。
2. 同一文または同一段落に、①数値 ②固有の対象(システム名・チーム名・業務名) ③観測可能な状態変化(「〜が…になる」)のいずれも無い。

### Step 5: 成功基準の3問バッテリー
成功基準に分類された各P(ゼロなら「成功基準なし」として判定表の行4へ)に:
- Q1: 測定対象が名詞で特定できるか(何を測る?)
- Q2: 達成値または観測可能な到達状態が書かれているか(どうなれば達成?)
- Q3: 判定時点・期限・判定者のいずれかが書かれているか

判定: Q1またはQ2がNo → **検証不能(Major)**。Q1・Q2はYesでQ3のみNo → **Minor**。

### Step 6: 貢献チェーンの再構成(4スロット)
次の表を、文書内の引用(P番号)**だけ**で埋める。埋まらないスロットには【断絶】と書く。スロット間の矢印について、文書内に因果の根拠(「〜により」「〜ことで」+理由の記述)が無ければ「? 仮定」を付ける。

| スロット | 引用(P番号) or 【断絶】 |
|---|---|
| 施策 | |
| 直接の効果 | |
| 対象者(ユーザー/チーム/顧客)の変化 | |
| プロダクト/事業への効果 | |

**空欄をレビュアーの想像で埋めることを禁止する。** レビュアーが好意的に補完しても、実際の読み手が同じ補完をする保証はない。

### Step 7: 重要度判定と出力
検出した各問題に下の判定表を**上から順に**適用し、最初に一致した行の重要度を採用する。指摘には該当行番号を控えておく(セルフチェックで使う)。出力フォーマットに従って書き、出力前セルフチェックを通してから出力する。

## 重要度判定表(上から順に評価し、最初に一致した行を採用)

| 行 | 条件 | 重要度 |
|---|---|---|
| 1 | Step 1で抽出ゼロ、またはWhatが「なし」 | Critical |
| 2 | Whatの全Pが手段判定(テストA+B確定) | Critical |
| 3 | 貢献チェーンのスロットが3つ以上【断絶】 | Critical |
| 4 | 成功基準がゼロ、またはQ1/Q2がNo | Major |
| 5 | チェーンの【断絶】が1〜2箇所、または要所の矢印が「? 仮定」 | Major |
| 6 | Whatが3個以上並列で優先順位の明示なし | Major |
| 7 | Whyに数値・頻度・固有事例が0件 | Major |
| 8 | Why now(なぜ今か)の記述なし・承認系文書 | Major |
| 9 | Why now の記述なし・非承認系文書 | Minor |
| 10 | 抽象語シェルター(行1〜9に含まれない箇所) | Minor |
| 11 | 非目的(やらないこと)の未記載 | Minor |

## 出力フォーマット

以下の構造を厳守する。**見出しの追加・削除・順序変更・改名を禁止。** 各指摘は5行以内。

```
## 判定サマリ(3行以内)
最も重要な問題と、直せば何が変わるか。問題がなければ「目的定義に重大な問題なし」と明言する。

## 欠落マトリクス
Why / What / Benefit / 成功基準 × 明確・弱い・なし(判定根拠のP番号付き)

## 指摘(重要度順・詳細は最大7件)
[C-1] 原文引用: 「...」(P番号)
  問題(パターン名): / なぜ問題か: / 修正案(または著者への質問N):
8件目以降は「その他: N件(種別のみ)」に畳む。

## 書き直し案
文書内の情報だけで書ける範囲の目的セクション改訂版。埋められない箇所は【要確認: 質問N】でマークする。

## 著者への質問
情報不足で判断・修正できなかった点。重複を除き、番号付きで、答えやすい形で。
```

## 出力前セルフチェック(全問Yesになるまで出力しない)

1. すべての指摘に「」付きの原文引用とP番号があるか。
2. 修正案・書き直し案に含まれる数値・固有名詞・事実を1つずつ原文と照合したか。原文に無いものは【要確認: 質問N】に置換したか。
3. 詳細指摘は7件以内か(超過分は件数と種別のみに畳んだか)。
4. 各指摘の重要度を判定表の行番号で説明できるか。
5. 出力の見出し構成はフォーマットと完全一致か。
6. 問題が無い観点は「問題なし」と明言したか(水増し指摘をしていないか)。

## レビュアーのアンチパターン(禁止行動)

- **好意的補完**: 書かれていない因果を「まあ繋がるだろう」と補って合格にする。→ 補完が必要な時点で断絶と判定する。
- **修正案の捏造**: もっともらしい数値・便益を発明して修正案を完成させる。→ 【要確認】+質問に変換する。
- **全文リライト**: 目的セクション以外まで書き直して著者の判断余地を奪う。
- **引用なし指摘**: 「全体的に目的が弱い」のような浮遊した指摘。→ 必ず特定のPに紐付ける。
- **件数での価値演出**: 問題が少なければ少ないと言う。レビューの価値は件数ではなく直したときの効果。

## 文書がまだ無い場合(壁打ちモード)

「これから書く」「目的がまだ固まっていない」場合は、references/purpose-template.md を開き、質問駆動で一緒に埋める。順序は Why → What → 成功基準 → Benefit。一度に全部聞かず、1〜2問ずつ進める。埋まった内容には本スキルのStep 3〜6を適用してセルフレビューしてから返す。
