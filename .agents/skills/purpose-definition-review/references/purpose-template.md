# 目的定義テンプレート(壁打ちモード用)

文書がまだ無い、または目的セクションを作り直す場合に使う穴埋めテンプレート。著者と対話しながら上から順に埋める。一度に全部質問せず、1〜2問ずつ。埋まらない欄は空欄のまま【要確認】と明示して残す(埋まっていないことが見えるのも成果物)。

## テンプレート

```
### 背景と課題
- 現状の事実: (数字・頻度・具体例で)
- それによる問題: (誰が・何に・どれくらい困っているか)
- 放置した場合: (コスト/リスク/機会損失。Why now があればここに)

### 目的(達成状態)
この取り組みが終わったとき、「____________」が成立している。
(1文。手段を書かない。第三者が達成/未達成を判定できる表現で)

### 成功基準
- 何を測る:
- どうなれば達成:
- いつ・誰が判定:

### 便益・貢献チェーン
施策 → (直接の効果) → (対象者の変化) → (プロダクト/事業への効果)
※ 矢印ごとに、確かな因果か仮定かを区別する。仮定には(仮定: 根拠)を添える。

-
```

## 質問の進め方

1. まずWhyから: 「そもそも今、何に困っている? 具体的なエピソードか数字はある?」
2. What: 「これが終わった日、何が『できるようになっている』と言えたら成功?」
3. 成功基準: 「それ、どうやって測る? 測れないなら、達成したと誰がどう判断する?」
4. Benefit: 「それが実現すると、次に誰が助かる? その先でプロダクト/事業の何が良くなる?」
5. 回答が埋まったら failure-patterns.md と突き合わせてセルフチェックしてから返す。

## 記入例(フィクション)

```
### 背景と課題
- 現状の事実: 認証基盤の設定変更は管理画面で手作業。直近半年で環境間の設定差分に起因する障害が3件。
- それによる問題: 障害のたびに原因特定に平均4時間、開発2名が対応に張り付く。
- 放置した場合: 環境が増える来期は差分の発生源も増え、障害頻度の増加が見込まれる。

### 目的(達成状態)
環境間の認証設定差分に起因する障害が発生しない状態(設定がコードで一元管理され、差分が自動検出される)。

### 成功基準
- 何を測る: 設定差分起因の障害件数 / 差分検出の自動化率
- どうなれば達成: 導入後2四半期で該当障害0件、全設定項目の差分がCIで検出される
- いつ・誰が判定: 四半期レビューで運用チームリーダーが判定

### 便益・貢献チェーン
IaC化 → 差分がCIで検出される → 差分起因の障害0件 → 開発2名×4時間/件の割込みが消え機能開発に充当 → ロードマップ遅延の主因(直近: 障害対応割込み)を解消

### 非目的
- 認証基盤そのものの機能追加・リプレイスは扱わない
```
