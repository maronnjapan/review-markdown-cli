# 読み手タイプ別・問いテンプレート

読み手が文書に無意識に投げかける問いの標準セット。該当タイプをベースに、**必ずこの文書固有の問いを1つ以上追加**してから充足マトリクスを作る。読み手が答えを見つけられない問いは、そのまま追撃質問・差し戻し・スルーになって返ってくる。

## 承認者・意思決定者(稟議、提案書、投資判断)
1. 私は何を求められている?(承認/予算/人/判断)
2. いくら・いつまで・誰がやる?
3. やると何が良くなる?(便益の主語と大きさ)
4. やらないとどうなる?(放置コスト)
5. リスクは何で、どう手当てする?
6. 代替案は検討した? なぜこの案?
7. なぜ今?
8. 撤退条件・見直し条件はある?

## 上長への報告(進捗、障害、相談)
1. 結論は?(順調/遅延/問題あり)
2. 私の判断・介入は必要? 必要なら何を?
3. 次に何が起きる? 次の報告はいつ?
4. (問題がある場合)影響範囲と現在の対処は?

## 実装者・作業者(設計doc、依頼、仕様)
1. ゴールと完了条件は?
2. 決まっていること/まだ決まっていないことの境界は?
3. 制約は?(技術、期限、互換性、セキュリティ)
4. インターフェース・入出力は?
5. 優先順位は? 何から着手する?
6. 不明点は誰にいつ聞ける?

## 社外・顧客(提案、依頼、通知)
1. 私(受け手)にとっての利益は?
2. 具体的に何をすればいい?(依頼事項)
3. 前提条件・費用・期限は?
4. 何かあったときの連絡先・保証は?

## 経営層(戦略提案、投資)
1. 事業インパクトは?(売上/コスト/リスクの規模感)
2. 投資対効果と回収時期は?
3. 最大のリスクと、顕在化したときの損失は?
4. 競合・市場の文脈で、なぜ我々が・なぜ今?

## レビュアー(技術レビュー、PR)
1. 何が変わる? なぜ変える?
2. どこを重点的に見てほしい?
3. 影響範囲と互換性は?
4. テスト・検証はどうした?

## 固有問いの作り方(機械手順)

1. SKILL.md Step 1 で書いた読後アクション文「主読者はこれを読んで◯◯する」を取り出す。
2. ◯◯を実行するために必要な情報・判断材料を列挙する(例: 承認する→金額の妥当性を測る材料、実装する→未決事項の境界)。
3. 各材料を疑問文に変換する。
4. 上のテンプレ問いと重複しないものだけを固有問いとして追加する(最低1つ)。
- 例: パスキー導入提案(承認者)→ 読後アクション「導入を承認するか判断する」→ 材料「既存認証との関係が分からないと運用影響を判断できない」→ 固有問い「既存のパスワード認証は廃止か併存か?」

## 使い方の注意
- 主読者を1人決める。「全員向け」の文書は誰の問いにも最適化されず、結果として誰にも刺さらない。
- 問いの順序は、そのまま文書の構成順序の有力な候補になる(SKILL.md Step 6 の再構成案で使う)。
